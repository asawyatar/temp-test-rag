# Fixtures: synthetic, not real data

Everything in this folder is **invented for testing**. The two communities,
"Qamar Bay" and "Rimal Terrace", do not exist. No real resident, unit, price
or policy appears here, and no file contains personal data.

| Folder | Stands for | Language mix |
|---|---|---|
| `tenant_a/` | Qamar Bay (خليج القمر) | Rules, maintenance, bookings, FAQ (JSON), safety guide (PDF) in English; fees, visitors, lease guide (Word) in Arabic |
| `tenant_b/` | Rimal Terrace (شرفة الرمال) | Rules, maintenance, bookings, FAQ (JSON), safety guide (PDF) in Arabic; fees, visitors, lease guide (Word) in English |
| `shared/` | Content every tenant sees: synthetic app help (`app-help.*`) and the **Atar app guide** (`01-…` to `18-…`, 18 topics in Arabic and English pairs) | English and Arabic |

Each tenant has all four formats: Markdown, JSON, Word and PDF. The Word and
PDF files are generated by `scripts/build_fixtures.py` (PDFs are printed by
headless Chrome, like many real PDFs) and committed, so tests never need to
regenerate them.

Where each format carries its "synthetic" label, which never reaches a chunk:

| Format | Label location |
|---|---|
| Markdown | Leading HTML comment (the loader strips comments) |
| JSON | `_fixture` field (the loader reads only `title` and `records`) |
| Word | Document properties → Comments |
| PDF | Document metadata → Subject |

## Why they look the way they do

- **The two tenants deliberately conflict.** Pool hours, fees, visitor limits
  and response times all differ, so an answer that leaks across tenants is
  wrong in a way a test can detect.
- **Each tenant covers each topic in one language only.** A question in the
  other language can only be answered by cross-lingual retrieval.
- **Each `notice-board` file contains a prompt-injection attempt.** The text
  tells an AI assistant to ignore its rules. The service must treat it as
  document content, never as an instruction.
- **Some topics are missing on purpose** (school buses, prayer times, EV
  charging) so the evals can ask questions the content cannot answer.

Every synthetic file starts with a `SYNTHETIC FIXTURE` label. The Atar app guide is
real app documentation (no personal data); its pages are identified by their front
matter (`title`, `language`, `topic`, `pair`), which the Markdown loader reads as
metadata. Every file in `tenant_a/` and `tenant_b/` is synthetic. The Markdown loader
strips HTML comments, so the label never reaches a chunk.
